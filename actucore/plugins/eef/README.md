# eef

在画布上连接 `eef_state → eef → servo_eef`。这张临时测试卡按接收到的新鲜实测帧发送绝对目标，操作者用 `move_by` 输入相对运动，用 `cancel` 将在途目标改为当前实测位置。

| 话题 | 消息 |
| --- | --- |
| `/limx_tron2/state/eef` | `motus.eef/1`，四字段为 `schema`、`frame`、`stamp_ms`、`eef`。时间戳是实测采样时间。 |
| `/limx_tron2/control/eef` | `motus.control/1`，`mode=eef_pose`、`dof=16`，`values` 存放完整绝对目标，`frame=base_Link`。 |

两个向量都按左 TCP 位姿、左夹爪开口、右 TCP 位姿、右夹爪开口排列。位姿为 `x, y, z, qx, qy, qz, qw`，位置和开口以米计。启动时画布从下游 `servo_eef.info()` 取得 `control_interface` 并传给本卡。`eef` 核对维度、组顺序和单位，使用描述符中的笛卡尔边界、夹爪行程和时效参数。

每个发布实例拥有独立的 `source`，每个控制帧递增 `seq`。`stamp_ms` 是本次发布时间，`obs_stamp_ms` 是本次用于构造控制帧的反馈采样时间。持续追踪同一目标时，其余组仍使用本次采样的实测值。相同采样的重复发布保留其观测时间。有效期 `ttl_ms` 使用公共控制流工具根据预期频率和驱动看门狗计算。

空闲时，每收到一帧有效实测数据，卡片就把该帧的双臂位姿和夹爪开口原样发给 `servo_eef`。需要移动时，在卡片上选 `move_by` 和 `left` 或 `right`，填写要改变的分量。

| 字段 | 从当前实测状态出发的增量 |
| --- | --- |
| `dx_m`、`dy_m`、`dz_m` | 基座坐标系平移，单位 m。正向分别是前、左、上。 |
| `rx_rad`、`ry_rad`、`rz_rad` | 以当前 TCP 为中心、沿基座轴表达的旋转向量，向量长度为转角，单位 rad。 |
| `opening_delta_m` | 夹爪开口变化，单位 m。正值张开，负值闭合。 |

例如，`{"action":"move_by","arm":"left","opening_delta_m":0.016}` 请求在当前实测开口上张开 16 mm。若当前开口为 80 mm、描述符上限为 85 mm，本卡记录和持续发送的目标都是 85 mm。平移超出工作空间时，取当前点到请求点的线段与边界的第一个交点。旋转增量独立施加在选定 TCP 上。待保持的其他组持续回显实测值；若这些实测值本身超出硬限位，驱动拒绝该控制帧。

提交 `move_by` 会立即发送一帧绝对目标。每收到新鲜反馈，卡片将此次指令涉及的末端位姿或夹爪开口保持在目标值，其余组取这帧实测值。重复的新鲜观测也触发发布。后续 `move_by` 从下令时的实测值重新计算并覆盖旧目标。

选择 `cancel` 会在同一次调用发出最新实测值，并把原先受控组的目标固定在这次实测位置。其余组继续随反馈回显。运动中断和全局中断也执行 `cancel`。`stop` 关闭卡片、清除目标并释放话题连接。

反馈中断期间暂停发布。此时执行 `cancel` 仍会清除旧目标。若尚无新鲜实测，取消会返回 `waiting_for_state`，第一帧恢复的新鲜反馈将成为保持目标。反馈恢复时仍有有效目标则重新按本次实测构造控制帧。

`info.sample` 是最新实测帧，`info.last.command` 是最近一次尝试发布的指令，`info.last.status` 是发布结果。`info.last.state_stamp_ms` 保留本次目标的起始观测时间。`info.last.publish_count` 是该目标成功发布的帧数。
